# standard-repo · 项目仓库设计规范

**v1.1.0** 按主要交付物设计仓库，按研究方向索引项目。同一方向下的软件、数据集和实验报告可以有各自的发布周期。[版本记录](CHANGELOG.md)

| 要做的事 | 从这里开始 |
| --- | --- |
| 新建、拆分或合并项目 | 根据主要交付物选择[仓库类型与目录布局](docs/repository-types.md)。 |
| 验收一次改动 | 选定用户动作、输入和预期，按[验收设计](docs/verification.md)留存证据。 |
| 开发、测试或整理多机副本 | 使用[项目工作流程](docs/research-development-workflow.md)中的实测命令和索引示例。 |

## 共同规则

- **目录有明确归属。** 随实际功能创建目录，用职责命名。正式逻辑放所属包，示例和脚本调用同一实现。文档配图放 `docs/media/`，运行所需资产跟随其加载入口。
- **安装后能独立使用。** 遵循已有工具链和锁文件，用包资源机制或工具链约定定位文件。自有配置中的相对路径以配置文件为基准，已有 URI 和框架保留自身语义。
- **输入和结果可追溯。** 代码、配置和小资源可纳入 Git。共享资产保留权威来源，大数据和权重按版本或校验值引用。数据格式、数据发布和代码可独立编号。
- **按运行记录结果。** 自有应用可用 `outputs/<run_id>/` 保存生效配置、日志和报告。长期采集数据、正式发布的模型及 ROS 构建产物沿用各自的存储约定。
- **保护现场信息。** 提交可共享的示例配置，实际密钥、个人标定和本机覆盖值单独保存。运行快照先移除敏感值。
- **保留一个使用入口。** README 说明主要交付物和最短使用路径，较长的规范和操作说明链接到各自的维护位置。历史版本由 Git 保存。

## 整理一个项目

按[仓库整理流程](docs/migration.md)盘点目标项目。手工整理时直接使用这份文档；委托 Agent 时，把它和目标项目路径一起交给 Agent。例如：

> 请读取 `<规范仓库>/docs/migration.md`，只读盘点 `<目标项目>`。给出类型依据、建议移动的文件、受影响的引用和验证命令。

要实际迁移时，明确目标路径和实施范围。支持技能的工具也可以读取[可选技能入口](skills/standardize-repo/SKILL.md)。

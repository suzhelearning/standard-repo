# standard-repo · 抗 Slop 项目仓库设计规范

**v2.0.0** 把仓库设计成让人类与 Coding Agent 都不容易写出 Slop 的确定性软件花园（Software Garden）：按主要交付物划分边界，以用户动作地图（Feature Map）驱动验收，用可执行护栏替代反复口头提醒。[版本记录](CHANGELOG.md)

## 核心设计哲学

灵感来自 Lauren Tan (poteto) 的《All Code Is Slop (Except Mine)》。在 Agent 高频产出代码的环境下，仓库本身就是它的上下文与施工约束：

1. **目录即边界。** 用使用者和运行时能直接辨识的目录名编码进程、职责和依赖边界，不靠口头约定防止越界引用。
2. **仓库即样板。** Agent 会忠实复制仓库里已有的模式。不保留双份默认配置、复制粘贴的示例实现或无人维护的死代码。
3. **护栏胜于散文。** 约束按 **L0 散文 → L1 结构信号 → L2 不可错接口 → L3 确定性检查**逐级固化。同类错误第 2 次出现时，升格为 L2/L3 护栏而非追加文档警告。
4. **动作与证据优先。** 先写清使用者从哪个入口完成什么动作、如何观测成功，再定目录边界与验收脚本。

## 共同规则

- **单一权威来源。** 正式逻辑放所属包，示例和脚本调用同一实现；同一参数、Schema 或配置只在权威位置定义一次。
- **安装后独立运行。** 生态与工具链约定优先，用包资源机制定位随包文件；自有配置的相对路径以配置文件为基准，不隐式依赖仓库根目录。
- **数据、资产与产物分层。** 代码、配置与小资源进 Git；共享资产保留权威来源与逐项许可；大数据与权重按版本或校验值外置引用；本地运行产物归入忽略目录（如 `outputs/<run_id>/`）。
- **保护现场敏感信息。** 提交可共享的示例配置，密钥、个人标定和本机覆盖值单独保存；运行快照导出前移除敏感值。
- **保留单一阅读与验收入口。** README 说明主要交付物、最短使用路径与核心用户动作表，详细规范链接至各自维护位置。

## 整理一个项目

按[仓库修剪与迁移流程](docs/migration.md)盘点目标项目。手工整理时直接阅读该文档；委托 Agent 时，把它和目标项目路径一起交给 Agent。例如：

> 请读取 `<规范仓库>/docs/migration.md`，只读盘点 `<目标项目>`。给出三层定型依据、Feature Map、Slop 隐患、建议移动的文件、受影响的引用及待补护栏。

要实际迁移时，明确目标路径和实施范围。支持技能的工具也可加载[可选技能入口](skills/standardize-repo/SKILL.md)。

# 机器人项目仓库设计规范

> 状态：已确认采用四类标准仓库形式（软件、ROS 系统、资产、数据集）；具体目录细节仍可修订。不是行业统一标准，也不是已验证可运行的代码模板。
> 只维护本设计仓库，不修改其他项目，不实施合仓、目录迁移或设备操作。

## 1. 已确认：共同规则＋四类标准仓库

不强迫所有机器人项目长成一个目录树，也不按每个研究方向各复制一个模板。

**先按交付物与构建方式选类型，再按实际功能组织内部目录。**

| 类型 | 主要用途 | 核心差异 |
| --- | --- | --- |
| A 软件型 | RL、VLA、仿真、感知、数据处理、非 ROS 遥操采集 | 以可安装的软件包为中心；Python 默认，原生库可有变体 |
| B ROS 系统型 | 驱动、控制、导航、规划、ROS 遥操采集 | 包级构建、接口与 launch；源码仓库不等于运行工作区 |
| C 资产型 | 机器人、物体、环境及共享场景资源 | 以资源条目、格式、来源、许可与版本为中心 |
| D 数据发布型 | 数据集、采集结果发布、训练／评估集 | 以数据说明、格式、清单与外部存储为中心 |

已确认采用上述四种仓库模板，**不是把所有现有项目合并成四个实际仓库，也不是按 RL／Sim／VLA／teleop 分成四仓**。同一模板可用于多个项目，一个仓库也可组合必要职责；只有独立发布、消费、许可或环境需求成立时才拆仓。本次确认不包含创建业务仓库或迁移现有代码。

## 3. 扩大的范围如何落到结构上

| 项目方向 | 推荐起点 | 文件组织重点 |
| --- | --- | --- |
| RL、模仿学习、VLA | A | 策略／训练／评估／数据读取代码，实验配置，外部权重 |
| 仿真、任务基准、合成数据 | A，必要时消费 C | 环境与任务代码、场景配置、资源引用、生成数据 |
| 遥操作、重定向、在线数据采集 | A 或 B | 输入、机器人、录制、启动配置；现场标定不混入公共源码 |
| 数据清洗、渲染、导出、可视化 | A | 处理实现与输入数据分开；发布数据时可配 D |
| 感知、跟踪、重建 | A，ROS 集成时可配 B | 推理与原生扩展、权重、传感器配置、重建结果 |
| 运动规划、导航、控制 | 算法库 A，ROS 系统 B | 原生构建、包级资源、地图、launch 与参数 |
| 机器人／物体／环境资产 | C | 模型、网格、纹理、碰撞、来源、许可、版本 |
| 数据集与评估集交付 | D | 格式、清单、划分、许可、小样本、外部数据 |
| 部署、评估和性能验证 | 所属类型的按需扩展 | 部署描述与基准程序是源码；运行结果是产物 |

这覆盖本轮样本，不声称穷尽机器人所有方向。嵌入式固件、电路设计等尚未专项研究，不将本规范冒充其工程标准。

## 4. 所有类型共用的规则

### 4.1 按内容归属，不按文件后缀归属

- 正式实现放源码包或构建系统规定的位置。
- 用户选择的运行参数放配置位置；有逻辑的配置类可与源码相邻。
- 模型与网格是资产；由模型生成的 episode 是数据，不能混为一类。
- 薄辅助入口放 `scripts/` 或纯资源仓的 `tools/`，不复制第二套业务实现。
- 文档展示图片默认放 `docs/media/`，不与物理资产混放。
- 日志、视频、报告和 checkpoint 等运行生成物不进入正式源码目录。

### 4.2 不创建空架构

目录按需要出现，不把模板树全部实例化。一项功能先用一个文件，复杂到需要拆分再变成目录。

不默认引入 `core/`、`common/`、`managers/` 等难以判断归属的层。工具按用途命名，例如 `transforms.py`、`timestamps.py`，不建无限扩张的 `utils.py`。

### 4.3 安装和路径不依赖开发机偶然状态

- Python 包使用项目专属名称，不跨仓堆叠同名顶层包。
- 不靠修改 `sys.path` 或相邻仓库源码目录完成正常使用。
- 随安装包分发的默认配置和小资源通过包资源机制定位。
- 新自有文件配置中的相对文件路径默认相对于声明它的配置文件；ROS 资源 URI、引擎引用和现有配置框架保留原有明确语义，不强行改写。
- 依赖清单、锁文件和版本化资源引用应能说明环境来源。Pixi 是可选默认工具，不是所有项目的强制规范。

### 4.4 源码、资产、数据和产物有不同生命周期

- Git 管源码、配置、文档及适量小资源；大资源可通过 LFS 或外部存储交付，具体按许可与使用方式决定。
- 大型数据集和预训练权重默认外置，版本与获取方式需要可追溯。
- 共享资产只有一个权威来源；本地缓存不变成另一份随意修改的源模型。
- 正式发布的转换模型不一定是可删除缓存；必须区分源文件、发布表示和临时产物。
- 数据格式版本、数据集版本、代码版本分别记录，不强制永远同步编号。

### 4.5 现场信息与公共默认值分开

配置示例可以提交，实际设备连接信息按敏感性管理，密钥与个人标定默认外置。无需把普通非敏感机器人几何参数也当成秘密。

本地覆盖配置由 Git 忽略；运行有效配置可随结果保存，但先移除密钥等敏感值。不反写默认配置。

### 4.6 运行结果默认集中，尊重工具约定

新自有应用建议使用 `outputs/<run_id>/` 存本次配置快照、日志、报告和视频；长期采集数据另有明确存储位置。

ROS 的 `build/`、`install/`、`log/`，以及构建工具自己的缓存保留原约定并忽略提交，不为了“所有输出一致”重写工具行为。

### 4.7 入口与说明保持唯一

README 说明职责、安装、最短运行路径和文档入口；长说明放 `docs/`。同一主题只有一处权威说明，其他位置链接过去。

正式命令由所属工具链声明，调用已有实现。部署、示例、笔记本不能各维护一套算法。

不以 `old/`、`new/`、`backup/` 保留并行实现；历史由 Git 管理。真实需要支持的格式版本必须有明确用途，不等同于备份目录。

## 5. 本次研究对初稿的修正

1. 从“所有项目默认 Python src 布局”改为四类模板，保留原生库和 ROS 例外。
2. 不再建议一律用 YAML：运行参数与代码配置是不同内容，跟随实际框架。
3. 资产型仓库允许根级 `robots/objects/environments`，无需再套一个空软件外壳。
4. 区分可复用场景资产、任务参数、任务逻辑及一次运行的场景快照。
5. 区分数据处理软件与数据发布仓库。
6. `packages/`、`deploy/`、`schemas/`、`benchmarks/` 等有真实需求时允许出现，不默认创建，也不一概禁止。

## 6. 采用时的检查

- [ ] 能说明仓库主要交付物，以及为什么选择该类型。
- [ ] 每个目录都有真实内容，没有为了模板完整创建空层。
- [ ] 实现、默认参数、资源、数据及运行结果没有重复的权威副本。
- [ ] 构建和安装遵循所用生态，不依赖其他开发目录残留。
- [ ] 许可、资源来源、数据获取方式与现场信息归属明确。
- [ ] 文档目录示例与实际结构对应；正式命令实际运行后才标记可用。
- [ ] 实施迁移时验证受影响的导入、资源解析、启动和文件输出，文档检查不能代替运行验证。

本仓维护规范与迁移技能，不包含已生成的业务代码模板。已有业务仓库只有在用户明确指定目标并调用迁移时才会调整。

## 7. 自动迁移技能：standardize-repo

技能定义：[skills/standardize-repo/SKILL.md](skills/standardize-repo/SKILL.md)。

它由编码代理执行：自动读取项目、按交付物识别四类模板、建立路径映射、迁移文件、同步引用与构建配置、运行最小验证并更新目标文档。不是只生成目录树，也不是无条件批量移动文件。

### 调用方式

OMP 加载该技能后，使用：

```text
/skill:standardize-repo /path/to/project
/skill:standardize-repo /path/to/project --plan
/skill:standardize-repo /path/to/project --type assets
```

支持 `--type auto|software|ros|assets|dataset`，默认自动分类；省略路径时使用当前项目。默认实施迁移，`--plan` 严格只读，不写计划文件。上述为技能调用参数，不是已安装的独立终端命令。

当前机器安装方式：`~/.omp/agent/skills/standardize-repo` 符号链接指向本仓 `skills/standardize-repo`，因此规范与技能只维护一份。移动或删除本设计仓库后需要修复该链接。

当前会话的 `skill://standardize-repo` 查询尚未识别新增入口；安装路径及规范文件解析已验证。重新加载技能或开启新会话后再使用快捷调用。在入口被识别前，可以直接要求代理：

```text
读取 /home/fcl/repo/standard-repo/skills/standardize-repo/SKILL.md，
按该技能将 /path/to/project 转换成我的标准仓库。
```

这条直接读取方式不依赖新增技能的快捷入口。技能会从自身真实位置读取本文与类型规范，不相对于目标项目猜测标准位置；单独复制 SKILL.md 而不保留其规范引用不是完整安装。

### 安全与完成边界

- 保留未提交改动；覆盖冲突需确认，不自动清理工作树。
- 数据集、权重、受限资产、密钥和现场标定不默认搬动。
- 不自动合仓、跨仓修改、提交、推送、升级环境或操作真机。
- 保持算法、控制参数、公开契约和数据格式语义；迁移需要同步更新所有本仓引用。
- 缺少运行环境时明确报告验证受阻，不把目录移动或静态检查当作完整成功。
- 对本设计仓库自身只读分析，避免迁移过程中移动技能及权威规范。

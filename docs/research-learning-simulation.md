# 机器人学习与仿真仓库文件组织：一手样本

访问日期：**2026-10-14**。范围：Isaac Lab、ManiSkill、LeRobot、openpi、robosuite 的官方文档和各自 GitHub 一手源码；以下“观察”仅描述所读页面，“规范影响”是针对通用机器人仓库的设计建议，**不是**声称这些项目共享一套行业标准。仓库页面使用链接中的 `main` / `master` 分支，后续可能变化；没有克隆或运行上游工程。

## 1. Isaac Lab：任务、仿真基础与资产配置分包

- **用途与实际路径（观察）**：官方仓库 `source/` 下分别有 `isaaclab/`、`isaaclab_assets/`、`isaaclab_rl/`、`isaaclab_tasks/` 等扩展包；任务包分为 `source/isaaclab_tasks/isaaclab_tasks/direct/` 与 `manager_based/`，如 `direct/cartpole/cartpole_env.py`、同级 `agents/`。机器人定义在单独的 `source/isaaclab_assets/isaaclab_assets/robots/`，而非每个任务各放一份机器人模型。来源：[source 目录](https://github.com/isaac-sim/IsaacLab/tree/main/source)、[任务包](https://github.com/isaac-sim/IsaacLab/tree/main/source/isaaclab_tasks/isaaclab_tasks)、[cartpole 示例](https://github.com/isaac-sim/IsaacLab/tree/main/source/isaaclab_tasks/isaaclab_tasks/direct/cartpole)、[机器人配置](https://github.com/isaac-sim/IsaacLab/tree/main/source/isaaclab_assets/isaaclab_assets/robots)。
- **配置、资产、产物（观察）**：同一个 `direct/cartpole/agents/` 中有 `rsl_rl_ppo_cfg.py` 和 `rl_games_ppo_cfg.yaml`、`sb3_ppo_cfg.yaml`、`skrl_ppo_cfg.yaml`；Python/YAML 并存，配置应由任务和实际训练后端决定。`isaaclab_assets` 的自身说明区分用于实例化资产的 Python 配置、Nucleus 上主要托管的资产、扩展包 `data/` 中临时托管的本地资产；不能把 `isaaclab_assets` 包名误解成所有 USD 模型都入 Git。官方 RL 文档将训练日志示例标为仓库根的 `logs/<library>/<task>/<date-time>`。来源：[cartpole/agents](https://github.com/isaac-sim/IsaacLab/tree/main/source/isaaclab_tasks/isaaclab_tasks/direct/cartpole/agents)、[资产扩展说明](https://github.com/isaac-sim/IsaacLab/tree/main/source/isaaclab_assets)、[RL 脚本与日志文档](https://isaac-sim.github.io/IsaacLab/main/source/overview/reinforcement-learning/rl_existing_scripts.html)。
- **训练/评估入口（观察）**：`scripts/reinforcement_learning/rsl_rl/train.py` 与 `play.py` 是独立入口；官方文档示例用 `./isaaclab.sh -p scripts/reinforcement_learning/rsl_rl/{train,play}.py --task ...`，`play.py` 可指定 checkpoint。来源：[RSL-RL 入口](https://github.com/isaac-sim/IsaacLab/tree/main/scripts/reinforcement_learning/rsl_rl)、[官方运行说明](https://isaac-sim.github.io/IsaacLab/main/source/overview/reinforcement-learning/rl_existing_scripts.html)。
- **规范影响 / 边界（建议）**：仿真任务较多且基础包、任务包、资产配置需要不同依赖或发布周期时，可采用**多包/扩展模板**；小项目不应照搬整个 `source/isaaclab_*` 分层。任务实现、任务特定 agent 配置及共享机器人配置应能被明确定位；外部模型地址和本地缓存不等同于必须提交的 `assets/` 内容，也不要求配置必须 YAML。

## 2. ManiSkill：单包内任务与场景分工，基准算法示例另置

- **用途与实际路径（观察）**：`mani_skill/envs/tasks/` 包含 `tabletop/` 等任务族，`mani_skill/envs/scenes/` 存放场景相关代码；`mani_skill/utils/scene_builder/` 存放场景构建器。如 `mani_skill/envs/tasks/tabletop/pick_cube.py` 定义任务环境、初始化、`evaluate()` 成功判定和奖励，并调用 `TableSceneBuilder`。机器人实现放在 `mani_skill/agents/`。来源：[包目录](https://github.com/haosulab/ManiSkill/tree/main/mani_skill)、[任务族](https://github.com/haosulab/ManiSkill/tree/main/mani_skill/envs/tasks)、[场景构建器说明](https://github.com/haosulab/ManiSkill/tree/main/mani_skill/utils)、[PickCube 源码](https://github.com/haosulab/ManiSkill/blob/main/mani_skill/envs/tasks/tabletop/pick_cube.py)。
- **配置、资产、产物（观察）**：PickCube 从同级 `pick_cube_cfgs` 的 Python 数据读取机器人差异参数，不要求所有任务变为 YAML。包内 `mani_skill/assets/` 有部分静态资源、`.gitignore`；`mani_skill/__init__.py` 将非包资源根默认设为 `~/.maniskill/data`、示教根设为 `~/.maniskill/demos`，均可由 `MS_ASSET_DIR` 覆盖。下载资源的元数据集中在 `mani_skill/utils/assets/data.py` 的 `DATA_SOURCES` / `DATA_GROUPS`，包含 URI、目标路径以及部分校验和；`mani_skill/utils/download_asset.py` 能以 `--output-dir` 指定下载位置。**包内资源、远端资源及下载后的本地数据不是同一类东西**。来源：[任务源码](https://github.com/haosulab/ManiSkill/blob/main/mani_skill/envs/tasks/tabletop/pick_cube.py)、[包内资产目录](https://github.com/haosulab/ManiSkill/tree/main/mani_skill/assets)、[默认路径源码](https://github.com/haosulab/ManiSkill/blob/main/mani_skill/__init__.py)、[下载清单](https://github.com/haosulab/ManiSkill/blob/main/mani_skill/utils/assets/data.py)、[下载入口](https://github.com/haosulab/ManiSkill/blob/main/mani_skill/utils/download_asset.py)。
- **训练/评估入口（观察）**：`examples/baselines/` 分 PPO、BC、ACT、diffusion policy 等；`examples/baselines/ppo/ppo.py` 的官方 README 给出 `--env_id=...` 训练，以及同一脚本加 `--evaluate --checkpoint=...` 评估的示例，评估轨迹/视频也是运行生成数据，不是任务源文件。来源：[baseline 目录](https://github.com/haosulab/ManiSkill/tree/main/examples/baselines)、[PPO 说明](https://github.com/haosulab/ManiSkill/tree/main/examples/baselines/ppo)。
- **规范影响 / 边界（建议）**：可在单个仿真包中把 `tasks/`、`scene_builder/`、`agents/` 按真实职责拆开；任务成功定义和奖励仍属于任务代码，不宜把任务变成只装参数的目录。允许下载清单按环境 ID 关联远端资源，并区分基准算法示例与正式实现；研究型单文件 baseline 不必强制升级成统一的核心包接口。

## 3. LeRobot：算法代码和可发布数据集格式不同树

- **用途与实际路径（观察）**：`src/lerobot/` 中有 `policies/`、`datasets/`、`envs/`、`robots/`、`teleoperators/`、`configs/`、`scripts/`；`src/lerobot/configs/train.py`、`eval.py` 是 Python 配置定义，正式训练与评估实现分别见 `src/lerobot/scripts/lerobot_train.py`、`lerobot_eval.py`；根 `pyproject.toml` 定义依赖和命令入口。来源：[Python 包](https://github.com/huggingface/lerobot/tree/main/src/lerobot)、[配置目录](https://github.com/huggingface/lerobot/tree/main/src/lerobot/configs)、[入口目录](https://github.com/huggingface/lerobot/tree/main/src/lerobot/scripts)、[pyproject.toml](https://github.com/huggingface/lerobot/blob/main/pyproject.toml)。
- **配置、资产、产物（观察）**：`TrainPipelineConfig` 是 dataclass，支持 `output_dir`、周期 checkpoint、评估参数，并将训练配置命名为 `train_config.json`；`DatasetConfig` 可用 Hub `repo_id` 或外部本地 `root`，默认数据位置涉及 `$HF_LEROBOT_HOME`，不等于源包下 `datasets/`：后者是读取和写入数据集的**代码**。YAML 也存在于 `src/lerobot/configs/recipes/*.yaml`，但不代表全部训练配置均为 YAML。来源：[训练配置源码](https://github.com/huggingface/lerobot/blob/main/src/lerobot/configs/train.py)、[数据配置源码](https://github.com/huggingface/lerobot/blob/main/src/lerobot/configs/default.py)、[YAML recipes](https://github.com/huggingface/lerobot/tree/main/src/lerobot/configs/recipes)、[数据处理代码目录](https://github.com/huggingface/lerobot/tree/main/src/lerobot/datasets)。
- **数据发布形态（观察）**：官方 LeRobotDataset v3 文档描述一个**独立数据集**的 `meta/info.json`、`meta/stats.json`、`meta/episodes/`、`data/` Parquet 分片及 `videos/` MP4 分片，可从 Hub 获取或流式读取。此 `data/` 是数据集格式中的权威目录，不能简单归类为应用仓库应忽略的运行 `outputs/`。来源：[LeRobotDataset v3 官方格式说明](https://huggingface.co/docs/lerobot/lerobot-dataset-v3)。
- **规范影响 / 边界（建议）**：算法开发仓库可用单 Python 包与正式 `train`/`eval` 入口；当目标是发布示教数据时，应启用独立的**数据集发布模板**并保留上游约定的 `meta/data/videos` 格式和版本信息，不能硬塞进算法包 `assets/` 或当可删的本地运行产物。Python 类型配置、YAML recipe 和训练输出 JSON 快照共存，格式与加载入口应明确，非一律 `configs/default.yaml`。

## 4. openpi：训练服务端、轻量客户端与平台示例分离

- **用途与实际路径（观察）**：主实现 `src/openpi/models/`、`models_pytorch/`、`policies/`、`training/`、`serving/`；另有带自己 `pyproject.toml` 的 `packages/openpi-client/src/openpi_client/`；`examples/aloha_sim/`、`examples/aloha_real/`、`examples/libero/` 放各平台/基准接入与数据转换代码。`.gitmodules` 将 `third_party/aloha`、`third_party/libero` 声明为第三方子模块而非拷入主包。来源：[主包](https://github.com/Physical-Intelligence/openpi/tree/main/src/openpi)、[客户端包](https://github.com/Physical-Intelligence/openpi/tree/main/packages/openpi-client)、[仓库 README 与 examples](https://github.com/Physical-Intelligence/openpi)、[.gitmodules](https://github.com/Physical-Intelligence/openpi/blob/main/.gitmodules)。
- **配置、资产、产物（观察）**：`src/openpi/training/config.py` 的 dataclass 定义模型、数据转换、训练配置，`DataConfig.repo_id` 指向 LeRobot 数据集，`AssetsConfig.assets_dir` 可指向别的 checkpoint 的归一化统计等训练资产。官方 README 直接引用外部 `gs://openpi-assets/checkpoints/...` 权重，说明默认缓存为 `~/.cache/openpi`（可由 `OPENPI_DATA_HOME` 覆盖），微调产物保存在 `checkpoints/`；数据转化示例 `examples/libero/convert_libero_data_to_lerobot.py` 与训练数据本体分离。来源：[训练配置源码](https://github.com/Physical-Intelligence/openpi/blob/main/src/openpi/training/config.py)、[官方 README](https://github.com/Physical-Intelligence/openpi)、[LIBERO 转换器](https://github.com/Physical-Intelligence/openpi/blob/main/examples/libero/convert_libero_data_to_lerobot.py)。
- **训练/评估入口（观察）**：`scripts/compute_norm_stats.py`、`scripts/train.py`、`scripts/serve_policy.py` 负责统计量、训练和策略服务；官方 README 给出 `uv run scripts/train.py pi05_libero ...` 和运行服务后由 LIBERO 评估脚本请求的流程，`examples/libero/main.py` 是基准环境侧入口，不是第二套训练核心。来源：[官方 README](https://github.com/Physical-Intelligence/openpi)、[LIBERO 评估说明](https://github.com/Physical-Intelligence/openpi/blob/main/examples/libero/README.md)。
- **规范影响 / 边界（建议）**：当客户端与训练服务器确需不同依赖/部署环境时才选**多包模板**；仅为目录统一不应引入 `packages/`。平台示例和必要第三方源以明确来源隔离；数据、公开预训练权重、归一化统计与实验 checkpoint 应分别记录来源和去向，不能把权重伪装为可提交 YAML 配置。`third_party/` 是真实依赖例外，不是一般项目默认占位目录。

## 5. robosuite：任务代码、控制配置和 MuJoCo 模型资产并存

- **用途与实际路径（观察）**：`robosuite/environments/manipulation/lift.py`、`pick_place.py` 是任务环境代码，`robosuite/models/{arenas,objects,robots,tasks}/` 是模型装配代码；`robosuite/models/assets/{arenas,objects,robots,textures}/` 有模型 XML/几何素材。来源：[环境任务](https://github.com/ARISE-Initiative/robosuite/tree/master/robosuite/environments/manipulation)、[模型代码](https://github.com/ARISE-Initiative/robosuite/tree/master/robosuite/models)、[模型资产](https://github.com/ARISE-Initiative/robosuite/tree/master/robosuite/models/assets)。
- **配置、资产、产物（观察）**：控制器默认及机器人专用配置保留在 `robosuite/controllers/config/{default,robots}/`，格式为 JSON；`MANIFEST.in` 显式将控制器配置、模型资产和 demos/scripts 纳入包分发。文档示例中的 `robosuite/demos/demo_collect_and_playback_data.py` 使用 `DataCollectionWrapper` 产生 `.npz` 轨迹（默认临时位置 `/tmp`），不意味着轨迹应与模型 XML 共同打包。来源：[控制器配置](https://github.com/ARISE-Initiative/robosuite/tree/master/robosuite/controllers/config)、[打包清单](https://github.com/ARISE-Initiative/robosuite/blob/master/MANIFEST.in)、[官方 demo 文档](https://github.com/ARISE-Initiative/robosuite/blob/master/docs/demos.md)。
- **训练/评估入口（观察）**：官方 demo 文档描述 `demo_random_action.py` 用于选择环境/机器人/控制器，`demo_collect_and_playback_data.py` 收集和回放轨迹，`demo_video_recording.py` 记录视频；这些是仿真和数据收集示例，所读页面**没有**一个与 LeRobot 相同的通用训练/评估 CLI，不应杜撰。来源：[官方 demo 文档](https://github.com/ARISE-Initiative/robosuite/blob/master/docs/demos.md)、[包内 demos](https://github.com/ARISE-Initiative/robosuite/tree/master/robosuite/demos)。
- **规范影响 / 边界（建议）**：模型 XML 与相对引用的网格/纹理属于**要随安装包分发的静态资产**时，可以留在 Python 包内部并显式打包，而不必搬到根 `assets/`；参数格式尊重消费方的 JSON 约定。仿真库不自带训练框架时，规范只要求记录实际演示/采集入口，不强制造 `train.py`/`eval.py`。

## 归纳：建议的共同约束与模板分流

| 证据与差异 | 设计影响（建议） | 不适用的强制做法 |
| --- | --- | --- |
| Isaac Lab 有多扩展包，openpi 有独立 client 包；ManiSkill、LeRobot 的主要实现是单 Python 包 | 默认 **Python 算法/仿真单包模板**；仅当独立发布、隔离依赖或不同部署目标有实际需要时采用 **多包/扩展模板**。上游包路径不需逐字复制。 | 要求所有项目统一 `src/<package>` 且永不例外，或反过来默认 `packages/`。 |
| Isaac Lab、LeRobot 的 Python 配置与 YAML 共存；ManiSkill 任务参数可由 Python 模块表达，robosuite 使用 JSON | 配置契约强调“可定位、显式加载、与任务/后端关联”，新增项目可选一套默认格式，但应允许代码型配置和工具限定格式；输出中保存运行时实际配置并区分原始配置。 | 全仓只准 YAML；把任务奖励、场景构建和成功条件移入静态 YAML。 |
| ManiSkill 场景构建器与任务代码分开，robosuite 模型构造和 XML 资产分开；Isaac Lab 大型 USD 常在 Nucleus；robosuite 小型运行必需素材随包 | 区分 **场景/任务实现**、**配置/场景参数**、**模型/几何素材**；小而必须分发的模型可包内，巨大或许可受限者引用已版本化外部资源并保留获取记录。 | 所有静态资产必须根 `assets/`，或所有资产均下载且不需来源信息。 |
| LeRobot v3 数据集 `meta/data/videos` 是独立公开格式；OpenPI 引用外部数据/权重，Isaac Lab、LeRobot 等运行输出各有项目约定 | 实验 checkpoint、日志、评估视频应区分于源代码和可再分发的数据集；提供可配置的外部数据/权重根、运行输出位置。**数据集发布模板**保留其格式定义的 `data/`，与项目的可丢弃 `outputs/` 不是同义词。 | 数据/权重都提交到源码 `assets/`；或将发布数据集里的 `data/` 当作待忽略缓存。 |
| 不同项目有 `train.py`、`play.py`、`lerobot-eval`、基准客户端、PPO 单文件脚本和纯仿真 demo | 规范要求 README 说明**实际入口**及训练、评估、回放/采集的分工；入口可以是包命令、显式脚本或外部框架，只规定产物边界，不规定相同的命令名。 | 给没有训练代码的模型/纯资产/数据仓库硬造入口。 |

**模板选择建议**：此组样本直接支持 Python 算法/仿真单包、多包扩展/客户端、独立数据发布三种不同组织方式；**纯模型资产仓库**可只有资产、来源/版本/许可说明，未必有 Python 包。ROS 工作空间等其他生态是否另设模板需依据其自身一手样本决定，不能仅由本页五个 Python 为主的样本推出 ROS 目录要求。共同规范宜约束职责、来源、路径解析与输出边界，而非唯一的根目录树。

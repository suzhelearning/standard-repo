# 从用户动作设计仓库和验收

v1 用一个问题把目录设计和测试连起来：**使用者从哪个入口完成什么动作，我们怎么知道它成功了？** 先写出一个真实动作，再决定模块边界、样本和验证方法。小仓库在 README 放一行就够了。

## 七种交付物怎样留下证据

下表是可采用的验收例子。选当前改动最可能破坏的用户动作，把命令和预期写成别人能照着执行的一行。

| 类型 | 用户动作与输入 | 怎么观察结果 |
| --- | --- | --- |
| A 软件 | 导入一个小样本，修改一个标注，再撤销。 | 从正常入口重开，比较标签与原值，保留回归测试结果。 |
| B ROS 系统 | 由实际 launch 配置启动无硬件回放，读取一段已知消息。 | 核对话题、坐标系与时间戳。涉及真机时单列现场动作和结果。 |
| C 资产 | 在目标加载器打开一个带相对网格引用的模型。 | 检查网格能解析、单位和关节方向符合约定，记录加载器版本。 |
| D 数据发布 | 根据一个发布清单读取一个样本与对应划分。 | 比对摘要和字段，核对训练与留出集的标识交集。 |
| E 知识与出版 | 从首页打开一篇正文，跟随正文链接找到目标资料。 | 用实际出版物检查导航、图片和最终页面。 |
| F 实验研究 | 用报告里的配置、数据版本和固定样本重算一个指标。 | 对照记录值、容差及聚合口径，记录运行 ID。 |
| G 集成工作区 | 根据组件清单从干净检出组合两个实际组件。 | 核对各组件提交并运行一次跨组件握手或样本传递。 |

### 应用到灵巧手数据与 tracker

例如要防止坐标系错误一路传到训练端，可以把它落在数据读取接口。采集端写出坐标系和长度单位，标注端沿用同一会话定义，训练入口只接收能解析这些字段的轨迹。用两条小样本做验收：一条已知手部轨迹通过流水线后关节方向和尺度正确，另一条缺失单位时在读入阶段报出缺失字段。这样下一次换动捕来源或改 tracker，能定位是哪一段破坏了约定。

算法验收另看实际表现。锁定配置和权重后，在同一版数据和同一组留出动作上复核跟踪指标，报告同时保留最差动作及对应回放。目录完整、程序跑通与追踪质量各有自己的证据。

## v1 自己怎样验收

在仓库根目录运行以下离线检查，只需 Python 3.8 或更高版本：

```bash
python3 scripts/check_release.py --tag v1.1.0
```

在干净检出中运行此命令，核对版本、七种类型、整理流程及其引用。再从首页打开整理流程，确认能找到只读盘点和实施迁移两种模式。业务仓的实测命令见[工作流程实例](research-development-workflow.md)。

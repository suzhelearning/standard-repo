# 仓库整理流程

开始前确定目标项目、执行范围和模式。**只读盘点**交付迁移方案，**实施迁移**按明确的范围移动文件并更新引用。两种方式都使用同一份[共同规则](../README.md)、[类型与布局](repository-types.md)和[验收设计](verification.md)。

一次处理一个实际项目。按主要交付物自动选型，指定类型与构建或发布方式冲突时，先核实依据。只读盘点期间，直接给出结果；写计划文件、安装依赖和会写入缓存的检查均属于实施阶段。

## 盘点与计划

1. 读取目标仓库的 README、构建与发布清单、锁文件、正式入口和项目规则。Git 仓库用 `git status --short`、索引和必要差异区分既有改动，检查未跟踪文件、子模块、符号链接、LFS 和忽略项。非 Git 项目保留原管理方式。
2. 按主要交付物选择类型，给出文件证据。检查源码、配置、资源、数据和生成物的实际消费者，包括导入、资源 URI、模型相对路径、打包清单、CI、部署和文档命令。纯导航目录可报告“项目索引，无需迁移”。集成工作区只处理根层，成员仓另行指定。
3. 给出目标结构及 `原路径 → 新路径 → 受影响的引用 → 验证方法`，标明保留、移动或受阻。记录用户动作、代表性输入、期望结果及已知的基线失败。只读模式到此交付，验证命令标为待执行。

## 实施与验收

1. 每次处理一个能独立验收的功能。移动时同步修改全部本仓消费者，保持公开包名、CLI、数据格式及算法行为。保留资产字节、单位、许可和相对引用。生成物用已有入口重建。
2. 保留原有未提交内容。目标冲突或外部消费者会失效时暂停该项，其余独立项可继续。更新忽略规则前检查候选文件。仅清理由本次迁移腾空且已无消费者的目录。
3. 按验收设计运行受影响的最小检查。Python 包从隔离安装后的入口加载资源，原生包验证构建和无硬件入口，资产核对哈希并用实际加载器读取，数据集核对清单与小样本。缺少硬件或 SDK 时记录已验证的部分及剩余范围。迁移导致的回归应修复或精确撤回本批变更。
4. 将实际变化写入目标 README，按项目惯例同步已有变更记录。已经符合规范时报告“无需迁移”。再次运行时应得到一致的结构。

## 额外授权

- 覆盖、删除用户文件，变更权限，搬动大数据、权重、密钥、受限资产或现场标定，改变 LFS 或分发方式。
- 修改其他仓库、子模块或符号链接指向的外部文件。保留提交和未提交内容，避免用 stash、reset 或 clean 清场。
- 安装或升级系统依赖、大型下载、启动常驻服务、训练、连接真机或赋予运动权限。
- 提交、推送、更改远端或重写 Git 历史。报告敏感文件时仅记录类别和位置。

交付时说明状态（仅计划、已完成、无需迁移或部分受阻）、类型依据、实际移动与保留项、验证结果及阻塞原因。只有实际验证过的能力才标记为通过。

# 仓库修剪与迁移流程（Weed & Fence）

整理仓库不是一次性“把文件搬整齐”，而是修剪会诱导 Agent 复制坏模式的 Slop 隐患，并在新边界上立起防退化护栏。

开始前明确目标项目、执行范围和模式：**只读盘点**交付诊断与迁移计划；**实施迁移**在锁定基线证据后分批移动文件、更新引用并留下最小护栏。两种模式均遵循[核心哲学与共同规则](../README.md)、[仓库类型与边界契约](repository-types.md)及[Feature Map 与确定性护栏](verification.md)。

一次处理一个实际项目。按三层正交模型自动定型；指定类型与构建或发布入口冲突时，先核实证据。只读盘点期间不写入任何文件、不安装依赖、不运行会写入缓存的命令。

## 1. 盘点与计划（只读模式）

1. **摸清现状与真实入口**：读取目标仓的 README、构建与发布清单、锁文件、正式入口和项目规则。Git 仓用 `git status --short`、索引和必要差异识别既有改动、未跟踪文件、子模块、符号链接、LFS 与忽略项。非 Git 项目保留原管理方式。
2. **三层定型与抽取 Feature Map**：给出「核心交付原型 + 生态适配器 + 组织拓扑」的文件证据，并抽出 1–5 条核心用户动作（动作 → 唯一入口 → 样本 → 观察点）。纯导航目录报告“项目索引，无需迁移”；多仓 `workspace` 仅盘点根层，成员仓另行指定。
3. **审计 Slop 放大器**：显式检查 4 类会污染后续 Agent 产出的隐患：
   - **重复权威来源**：多份冲突的默认配置、被 `examples/` 或 `scripts/` 复制分叉的实现；
   - **边界越界与产物混放**：源码反向依赖示例、运行产物/大文件/绝对路径混入源码树、敏感或标定信息未隔离；
   - **入口漂移**：README 命令与真实入口不一致、无入口的孤立目录或死链；
   - **纯 L0 脆弱约束**：反复出错却缺少 L2 接口校验或 L3 离线检查的边界。
4. **交付只读方案**：输出目标结构、`原路径 → 新路径 → 受影响的消费者 → 验证动作`（标明保留、移动或受阻）、已知基线失败，以及**建议补齐的最小 L2/L3 护栏**。只读模式到此交付，所有验证命令标为待执行。

## 2. 实施与验收（迁移模式）

1. **先立基线证据，再动结构**：移动任何文件前，先按 Feature Map 跑通至少一条受影响的最小验证作为基线；若基线本身已失败，如实记录且不掩盖。
2. **小步迁移与同步消费者**：每次处理一个可独立验收的功能。移动文件时同步更新全部本仓消费者（导入、资源 URI、模型相对路径、打包清单、CI、部署与文档命令），保持公开包名、CLI、数据格式与算法行为不变；保留资产字节、单位、许可与相对引用；生成物由既有入口重建。
3. **保护现场与冲突止损**：保留原有未提交内容。遇到目标冲突或外部消费者失效时暂停该项，其余独立项可继续。更新 `.gitignore` 前检查候选文件；仅清理由本次迁移腾空且已无消费者的目录。
4. **验收并留下防退化护栏**：按[验收设计](verification.md)执行最小检查（`lib` 测隔离安装与资源加载，`app` 测真实入口或无硬件回放，`assets` 核哈希与加载器读取，`dataset` 核清单/Schema/Split，`content` 扫链接与构建，`research` 重算指标）。缺少硬件或 SDK 时如实记录已验证与未验证范围。整理完成后同步更新 README 与 Feature Map，并在目标仓留下至少 1 条最小离线护栏（L2 或 L3），防止后续提交退化。迁移导致的回归须立即修复或精确撤回本批变更。

## 3. 额外授权红线

以下操作必须获得明确授权后方可执行：
- 覆盖或删除用户文件、变更权限、搬动大数据/权重/密钥/受限资产/现场标定、改变 LFS 或分发方式。
- 修改其他仓库、子模块或符号链接指向的外部文件；使用 `stash`、`reset`、`clean` 清理未提交内容。
- 安装或升级系统依赖、执行大型下载、启动常驻服务、运行训练、连接真机或赋予运动权限。
- 提交、推送、更改远端或重写 Git 历史。报告敏感文件时仅记录类别和路径，不泄露内容。

交付报告须写明：状态（仅计划 / 已完成 / 无需迁移 / 部分受阻）、三层定型依据、Feature Map、Slop 隐患处理与保留项、验证证据、新增护栏及阻塞原因。只有实际执行并通过的能力才标记为通过。

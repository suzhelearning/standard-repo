# 遥操作、采集与资产组织：一手来源研究

访问日期：**2026-10-14**。范围是仓库组织规则研究，非运行、复现或迁移项目。下文「观察」仅指已读取的项目官方文档、作者 GitHub 目录或源码；「建议」是拟议规范，不代表上游规定。尤其区分**源码库里存在的目录**与**下载/采集后才产生的目录**。本文没有下载资产或运行机器人。

## 一手来源及实际组织

### 1. Open-TeleVision：遥操作程序与训练数据

- **用途与观察**：作者的 [仓库和使用说明](https://github.com/OpenTeleVision/TeleVision/blob/main/README.md)覆盖头显遥操作、仿真示例及模仿学习。实际控制代码集中在 [`teleop/`（`TeleVision.py`、`Preprocessor.py`、`teleop_hand.py`、`inspire_hand.yml`、`webrtc/`、`dynamixel/`）](https://github.com/OpenTeleVision/TeleVision/tree/main/teleop)；[训练/重放/后处理脚本](https://github.com/OpenTeleVision/TeleVision/tree/main/scripts)在 `scripts/post_process.py`、`scripts/replay_demo.py` 等。随仓库的 [`assets/h1_inspire/`](https://github.com/OpenTeleVision/TeleVision/tree/main/assets/h1_inspire)含 `urdf/`、`meshes/`、`launch/`、`package.xml`，这是**机器人描述资源**，不是示教录制或随意的实验输出。
- **采集与生成物**：README 要求另行下载数据集并放进 `data/recordings/`，随后 `scripts/post_process.py` 加工；这是**安装后的数据放置约定**，不能仅凭 README 当成已提交的数据。README 还要求在 `teleop/` 放本地生成的 `cert.pem`、`key.pem` 用于 HTTPS；[`.gitignore`](https://github.com/OpenTeleVision/TeleVision/blob/main/.gitignore)排除了 `*.pem`、`*.svo`、`*.mp4` 等，不应把这些密钥或录制物理解为发布资产。[根许可证](https://github.com/OpenTeleVision/TeleVision/blob/main/LICENSE)为 Apache-2.0，同时明确列出 ACT、DETR 等上游组件须分别查看许可。
- **借鉴/例外（建议）**：把遥操控制/传感预处理、设备配置、机器人模型、录制数据、加工脚本分清；程序若包含 ROS 风格 `package.xml` 机器人描述，可以按 ROS 包组织，**不要**仅因为外层叫 `assets/` 就把可执行遥操代码塞进资产库，也不要求所有库都复制此项目 `teleop/` 路径。

### 2. DROID：多设备采集、标定、原始与处理轨迹

- **用途与观察**：官方 [README](https://github.com/droid-dataset/droid/blob/main/README.md)称仓库用于搭建机器人平台并采集遥操作示教；[`droid/`](https://github.com/droid-dataset/droid/tree/main/droid)实际拆分 `calibration/`、`camera_utils/`、`controllers/`、`data_loading/`、`data_processing/`、`postprocessing/`、`user_interface/` 等；[`config/fr3/`、`config/panda/` 和 `.docker/laptop/`、`.docker/nuc/`](https://github.com/droid-dataset/droid)分别服务硬件及不同部署端。[`droid/calibration/calibration_info.json`](https://github.com/droid-dataset/droid/blob/main/droid/calibration/calibration_info.json)示例含按相机序列号与左右侧区分的 `pose`、`timestamp`；是**标定数据**，不等于可通用的设备静态配置。
- **数据落地与生命周期（上游明确规定）**：[`scripts/README.md` 的 Expected Data Directory Structure](https://github.com/droid-dataset/droid/blob/main/scripts/README.md#expected-data-directory-structure)要求 `<data_dir>/{success,failure}/<日期>/<轨迹时间戳>/trajectory.h5`，且有 `recordings/SVO/<相机序列号>.svo`；`failure/` 可选。相同文档说明 `scripts/postprocess.py` 校验轨迹、把 SVO 转 MP4、上传到 S3，`cache/postprocessing/<lab>-cache.json` 为处理缓存；**这是一条该项目上传工具依赖的严格采集数据 schema**，不是面向所有机器人的通用目录。官方 [标定流程](https://droid-dataset.github.io/droid/example-workflows/calibrating-cameras.html)要求相机移位后重标定；[采集流程](https://droid-dataset.github.io/droid/example-workflows/data-collection.html)明确实践轨迹不保存、场景变化影响标定。[上传说明](https://github.com/droid-dataset/droid/blob/main/scripts/README.md#quickstart)要求 AWS 凭据 JSON **不可纳入 Git**。
- **借鉴/例外（建议）**：采集原始流、按轨迹组织的传感/动作、成功失败标签、设备/相机标定与后处理缓存应具备独立语义和关联标识；运行时可配置数据根目录。静态配置可以版本化，真实设备标定须随设备、时间/场景变更管理并遵循隐私/共享策略。若为纯算法仓库，则不强制 `calibration/`、`recordings/`、`.docker/nuc/`。

### 3. MuJoCo Menagerie：按机器人型号自包含的纯模型库

- **用途与观察**：官方 [README 的 Overview](https://github.com/google-deepmind/mujoco_menagerie/blob/main/README.md#overview)明确一个型号一个目录：`unitree_go2/go2.xml` 是**机器人本体 MJCF**，`unitree_go2/assets/` 为外观/碰撞 mesh，`unitree_go2/scene.xml` 是包含本体、地面、灯光等的**示例场景**，并放 `README.md`（含生成说明）、`LICENSE`、预览图；`*_mjx.xml` 和 `scene_mjx.xml` 为按需存在的兼容变体。实际 [`unitree_go2/` 列表及 README](https://github.com/google-deepmind/mujoco_menagerie/tree/main/unitree_go2)说明 DAE mesh 经 Blender/obj2mjcf 转换为 OBJ、从 URDF 导出 MJCF；源格式、转换说明、发布模型及仿真场景是不同层次。官方 [许可证说明](https://github.com/google-deepmind/mujoco_menagerie/blob/main/README.md#license-and-disclaimer)要求查**每个型号目录内**的许可证；示例 [`unitree_go2/LICENSE`](https://github.com/google-deepmind/mujoco_menagerie/blob/main/unitree_go2/LICENSE)为 BSD-3-Clause，不可对整个模型集合概括成此许可。
- **借鉴/例外（建议）**：纯机器人资产库可以按型号邻接本体定义、依赖 mesh、转换来源说明、许可证与最小场景；复用时勿混淆机器人本体 XML 和示例 `scene.xml`，也不强制完整的 Python `src/`、训练目录、采集目录。转换所得几何与预览应注明来源、生成工具版本、是否版本化，不要将生成物无条件混进原始 CAD。

### 4. Objaverse-XL：外部物体索引、按对象许可及渲染衍生物

- **用途与观察**：作者 [仓库首页](https://github.com/allenai/objaverse-xl)明确仓库是**下载、处理脚本**，不是 3D 物体全集；实际代码在 [`objaverse/xl/`](https://github.com/allenai/objaverse-xl/tree/main/objaverse/xl)按 GitHub、Sketchfab、Smithsonian 等来源组织下载器，渲染程序在 [`scripts/rendering/`](https://github.com/allenai/objaverse-xl/tree/main/scripts/rendering)。[`objaverse/xl/__init__.py`](https://github.com/allenai/objaverse-xl/blob/main/objaverse/xl/__init__.py)声明 `get_annotations()` 返回含 `fileIdentifier`、`license`、`source`、`fileType`、`sha256`、`metadata` 的对象索引，`download_objects()` 以 `fileIdentifier`、`source`、`sha256` 获取对象，默认下载目录 `~/.objaverse`，可自定义。**这些是物体来源元数据，不是仿真场景实例或机器人模型。**
- **生成物与权利**：[`scripts/rendering/README.md`](https://github.com/allenai/objaverse-xl/blob/main/scripts/rendering/README.md)举例渲染输出在 `~/.objaverse/github/renders/`，每个对象 ZIP 包内有视角 PNG、相机矩阵 NPY、`metadata.json`；应与源物体文件分层。仓库 [README License](https://github.com/allenai/objaverse-xl#license)区分整体数据集 ODC-By 1.0、**各对象不同许可**，且 Polycam 来源有申请审批/学术非商业限制；代码仓库 [LICENSE](https://github.com/allenai/objaverse-xl/blob/main/LICENSE)的 Apache-2.0 不会替这些物体重新授权。
- **借鉴/例外（建议）**：外部物体可保存小型获取清单/索引（来源 URL 与 ID、版本/内容哈希、许可及获取条件），大文件放可配置缓存或受控外部存储；源网格与渲染、规范化、碰撞近似等派生物分层关联。纯下载/分发库未必需要 `scenes/`，未完成许可核查的对象不得因为索引公开就宣称可再分发。

### 5. ManiSkill：分别登记机器人、物体、场景、任务依赖

- **用途与观察**：项目 [资源注册表 `mani_skill/utils/assets/data.py`](https://github.com/mani-skill/ManiSkill/blob/main/mani_skill/utils/assets/data.py)的 `DataSource` 包含 `source_type`、URL/HF 仓库、`target_path`、可选 `checksum`；`DATA_GROUPS` 把资源归到任务/物体组。其中 `ycb` 指向 `assets/mani_skill2_ycb`，PartNet-Mobility 单对象到 `partnet_mobility/dataset/<model_id>`，场景 `ReplicaCAD`、`AI2THOR`、`RoboCasa` 分配 `scene_datasets/...`，独立机器人分配 `robots/ur10e` 等，任务布局另有 `tasks/...`。上述为**下载目标路径**，不是 Git 仓库已内置全部场景数据。[Quickstart](https://maniskill.readthedocs.io/en/latest/user_guide/getting_started/quickstart.html#task-instantiation-options)说明按环境 ID 下载任务资产；[当前源码](https://github.com/haosulab/ManiSkill/blob/main/mani_skill/__init__.py)将默认资源根设为 `~/.maniskill/data`，设置 `MS_ASSET_DIR` 后使用该目录下的 `data/`，并将示教放在同根的 `demos/`。[scene 文档](https://maniskill.readthedocs.io/en/latest/user_guide/datasets/scenes.html)表明场景资源适配自 RoboCasa、ReplicaCAD、AI2THOR，应另引原作者。路径以当前源码核对结果为准，不将文档示例中的 `~/maniskill/data` 当作统一默认值。
- **运行与许可**：官方 [demonstration 格式](https://maniskill.readthedocs.io/en/latest/user_guide/datasets/demos.html#format)用轨迹 HDF5 配同名 JSON，JSON 中 `env_info.env_id/env_kwargs`、每 episode 的 `reset_kwargs` 支撑**环境/场景实例复现**，不能拿下载的 mesh 路径代替；[`scripts/data_generation/`](https://github.com/mani-skill/ManiSkill/tree/main/scripts/data_generation)为生成脚本。[仓库 README License](https://github.com/mani-skill/ManiSkill#license)分别说明代码/刚体环境与资产许可，资产标为 CC BY-NC 4.0；对底层第三方场景/对象仍应核验其原始分发条款，而非从代码 Apache-2.0 推定全部资产可商用。
- **借鉴/例外（建议）**：资产登记表可驱动按任务下载/校验，把机器人本体、物体、环境场景、任务配置分开；轨迹保存能重建场景实例的任务 ID、重置参数与资产版本。小项目只依赖少量公开模型时不必实现完整下载管理器，可用可阅读的清单。

### 6. BEHAVIOR-1K：符号任务、场景实例、加密资产与转换流水线

- **用途与观察**：[官方 Important Concepts](https://github.com/StanfordVL/BEHAVIOR-1K/blob/main/docs/getting_started/important_concepts.md)明确区分：BDDL 符号任务（对象范围、初始/目标条件）、具体物体模型（category + 唯一模型 ID）、场景基底、采样产生的任务实例以及粒子系统；**场景布局与任务实例不是同一份静态物体网格**。代码仓库 [`OmniGibson/omnigibson/configs/`](https://github.com/StanfordVL/BEHAVIOR-1K/tree/main/OmniGibson/omnigibson/configs)有运行配置，根目录含 `bddl3/`、`OmniGibson/`、`asset_pipeline/` 和 [`datasets/` 占位目录](https://github.com/StanfordVL/BEHAVIOR-1K/tree/main/datasets)。占位目录 [`.gitignore`](https://github.com/StanfordVL/BEHAVIOR-1K/blob/main/datasets/.gitignore)排除下载数据；**不能把下载后的场景/物体误写成仓库已提交文件**。
- **已验证的路径契约**：[当前 `macros.py`](https://github.com/StanfordVL/BEHAVIOR-1K/blob/main/OmniGibson/omnigibson/macros.py)默认把 `gm.DATA_PATH` 指向仓库 `datasets/`，可由 `OMNIGIBSON_DATA_PATH` 覆盖；[`asset_utils.py`](https://github.com/StanfordVL/BEHAVIOR-1K/blob/main/OmniGibson/omnigibson/utils/asset_utils.py)读取 `<DATA_PATH>/behavior-1k-assets/scenes/<scene>`、`objects/<category>/<model>`、`systems/` 和 `metadata/categories.txt`，将 2026 challenge 的任务实例另放 `<DATA_PATH>/2026-challenge-task-instances/{scenes,scene_test/...}/<scene>/json/<instance>.json`。这是**源码中定义的下载数据读取路径**，非本次实际下载核验。官方 [安装指南](https://behavior.stanford.edu/getting_started/installation.html)的 `--dataset` 需接受 BEHAVIOR 数据集条款；[来源说明](https://behavior.stanford.edu/behavior_components/asset_sources.html)称不少资产采购自 TurboSquid，发行加密加工版本遵守原许可。
- **加工链与许可**：[上游 `asset_pipeline/README.md`](https://github.com/StanfordVL/BEHAVIOR-1K/blob/main/asset_pipeline/README.md)把 `cad/scenes/`、`cad/objects/` 的 3ds Max 源、`metadata/`、`b1k_pipeline/`、DVC 定义及 `artifacts/pipeline/` 中间、`artifacts/aggregate/` 聚合、`artifacts/og_dataset.zip` 交付物区别开；原始 `.max` 受限，不向非斯坦福人员发布。官方概念文档进一步说明 BEHAVIOR 场景 JSON 是对象布局/状态，物体 USD 及贴图、系统定义为另一层。根仓库 [MIT LICENSE](https://github.com/StanfordVL/BEHAVIOR-1K/blob/main/LICENSE)不意味着受限原始 CAD 或加密数据转为 MIT。
- **借鉴/例外（建议）**：可追溯地分离原始受限 CAD、转换源代码/参数、中间件、可发布打包资产、独立场景布局、任务实例；但不应给不具备授权和规模的小仓库强制 DVC、加密或 BEHAVIOR 的多组件 monorepo 树。

## 收敛：共同语义与少量模板族（均为建议，不是照抄上游）

1. **共同语义先于目录名**：在项目入口指明代码、配置、原始资源、安装后外部资源、生成/转换物、录制数据、标定与场景实例各在哪里；同名 `assets/` 在 Menagerie 是**机器人 mesh**、在 TeleVision 是**机器人描述**、在 `docs/assets/` 则可能只是文档图，不能以词形断言版权或语义。场景文件与本体模型不可互换：Menagerie `scene.xml` 是演示环境，BEHAVIOR 场景 JSON 是可采样任务的物体布局，ManiSkill 轨迹 JSON 中重置参数是每次实例化条件。
2. **模板族可选**：①遥操/采集程序：控制与设备配置 + 标定 + 可配置的仓外或忽略的原始录制根 + 后处理/发布根；②纯机器人模型库：`<model>/` 内邻接描述、mesh、来源/许可证和可选示例场景；③外部资产索引/数据发布：可版本化清单/下载器 + 仓外缓存 + 派生输出 + 分项权利信息；④若同项目同时承担大量算法和资产管线，按组件边界组织（如 BEHAVIOR），而非强制单一 Python `src/` 树。ROS 描述包需保留 `package.xml`/`urdf`/`meshes` 惯例，按其实际打包边界，不为统一改成算法模板。
3. **获取清单建议字段**：资源类别（robot/object/scene/environment）、上游及原始下载 URL/稳定 ID、版本/commit、哈希、文件格式及单位/坐标系、许可与逐项归属/再分发限制、下载目标/缓存根、转换工具和参数、衍生目标、被哪些场景或任务引用。来源与许可及获取限制为必要判定，没提供哈希时如实记 `未提供`，不要伪造；大文件默认不进 Git，是否纳入版本库按来源许可、体积与复现要求决定。
4. **实验/采集的关联键**：一条示教包含设备/相机标识、标定版本与有效期、场景/物体资源 ID 及版本、任务与实例化参数、原始流位置、轨迹格式、处理版本和成功失败/质检标签；设备敏感参数与密钥不能充作公共示例配置。处理或转换结果可再生成时与原始数据分根并记录输入和工具版本，发布数据可以有与采集工作站完全不同的目录 schema。
5. **适用例外**：没有采集硬件不必建空 `calibration/`；只发布模型不必建 `data/recordings/`；只索引外部物体不必复制数百万网格；只有机器人模型与一个演示场景不必引入 BEHAVIOR 的对象-场景-任务实例多层目录。是否采用单仓、多包或单独资产/数据仓库，取决于发布物、许可和操作链，而不是强求一种目录树。

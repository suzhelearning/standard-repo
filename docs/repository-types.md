# 仓库类型与边界契约

> 规范版本 v2.0.0。目录结构为边界服务，框架、宿主与出版平台规定的原生入口优先。

早期机器人项目的一手结构样本见[学习与仿真](research-learning-simulation.md)、[遥操作与资产](research-teleop-assets.md)、[系统与数据发布](research-systems-data.md)。每种类型均需配套[Feature Map 与确定性护栏](verification.md)。

## 1. 三层正交定型模型

v2.0 不再用一维列表混装“交付物、技术栈和多仓拓扑”，而是按三个正交维度定型：

1. **核心交付原型（6 类）**：按使用者如何消费、如何验收、禁止哪些越界划分。
2. **生态适配器（Toolchain Profile）**：决定构建清单、包路径与运行入口（Python、ROS、CMake/C++、Web/Node、宿主插件、框架扩展等）。
3. **组织拓扑（Topology）**：单包单仓、多包单仓（`packages/`）或多仓集成工作区（`workspace`）。

### 核心交付原型选型表

| 类型 | 交付原型 | 消费方式 | 适用场景 | 不适用情况 |
| --- | --- | --- | --- | --- |
| `lib` | 可复用包 / 库 | 被其他代码 import、链接或作为依赖安装 | 算法库、SDK、传感器驱动包、C++ 原生库、仿真环境包 | 面向终端直接交互运行的应用选 `app` |
| `app` | 可运行应用 / 系统 | 由人、服务或硬件直接启动、交互或编排运行 | CLI、Web 查看器、宿主插件、遥操采集系统、ROS bringup 系统、板端程序 | 纯供调用的底层库选 `lib`；纯资产选 `assets` |
| `assets` | 物理与场景资产 | 由仿真器、渲染器或多项目按 ID 加载 | 机器人模型、物体、静态环境、可复用组合场景 | 大量采集轨迹与训练权重不属于物理资产 |
| `dataset` | 版本化数据发布 | 由训练或评测流水线按清单与划分读取 | 采集数据发布、训练数据集、标准评估集 | 通用清洗/训练软件本身选 `lib` 或 `app` |
| `content` | 知识与出版 | 由读者在线浏览、检索或构建导出阅读 | 知识库、工程规范、学术主页、论文源稿 | 交互式软件产品选 `app` |
| `research` | 可复核实验研究 | 由复核者按配置、数据版本与运行 ID 重算对照 | 消融研究、横向评测、定稿实验报告 | 可复用评测框架选 `lib`/`app`，独立测试集选 `dataset` |

> **多仓组织拓扑**：`workspace` 用于组合多个独立仓库（`.gitmodules`、ROS `.repos` 或组件清单），只治理根层版本锁定与跨仓握手，不替代成员仓类型。
> **v1 别名兼容**：`software` 按主要消费方式展开为 `lib` 或 `app`；`ros` 按单包驱动/消息库或系统启动展开为 `lib` 或 `app` 并启用 ROS 生态适配器。

## 2. 六类核心原型与多仓拓扑契约

每个原型采用统一四段结构：**交付物与入口**、**布局与生态优先**、**禁止越界**、**最小可执行不变量**。示例目录按需创建，不为空目录建壳。

### `lib`：可复用包 / 库

- **交付物与入口**：可安装或可链接的公共 API（Python 包、C++/CUDA 库、ROS 接口/驱动单包），由包清单明确导出符号、版本与依赖。
- **布局与生态优先**：默认 Python 采用 `src/<package>/`、`tests/`、`examples/`、`docs/`、`pyproject.toml`；C++/混合语言采用 `include/<project>/`、`src/`、`bindings/`、`cmake/`、`tests/`、`benchmarks/`、`CMakeLists.txt`；ROS 单包库保留 `package.xml` 与 `ament` 约定；扩展 Isaac Lab 等框架保留原生 `source/` 与注册路径。需要随包安装的默认资源放包内并通过包资源机制加载。
- **禁止越界**：禁止 `src/` 反向导入 `examples/`、`scripts/` 或 `notebooks/`；禁止在代码里硬编码仓库根目录或本机绝对路径；禁止在 `pyproject.toml` 与环境锁文件中手工维护两套冲突依赖约束；禁止把训练权重或原始数据集实体打入源码包。
- **最小可执行不变量**：在隔离安装环境（不依赖当前工作目录）可成功导入公开入口、加载随包资源并跑通关键行为测试；核心数据结构或单位契约对非法输入直接抛错。

<details>
<summary>常见 Python / 算法模块候选命名与多包拆分说明</summary>

- **按方向可选子模块**（小项目先用同名 `.py`）：RL/VLA 用 `policies/`、`training/`、`evaluation/`、`datasets/`（数据处理代码，非实体）；仿真基准用 `envs/`、`tasks/`、`sensors/`、`rendering/`；感知重建用 `perception/`、`tracking/`、`reconstruction/`；规划控制用 `kinematics/`、`planning/`、`control/`。
- **配置边界**：依赖类与类型检查的配置可与实现相邻（Python dataclass/TypedDict），不要强行改写成 YAML；同一参数只留一份权威定义。
- **多包单仓**：仅当服务端与轻量客户端依赖隔离，或框架要求多扩展包时，使用 `packages/<pkg>/` 各自维护清单与测试。

### `app`：可运行应用 / 系统

- **交付物与入口**：面向用户、服务或硬件的可执行入口（CLI 命令、Web 路由、宿主插件 manifest、遥操/采集运行时、ROS `launch/` 系统启动组合）。
- **布局与生态优先**：保留宿主与框架原生约定——Web 应用沿用框架路由、静态资源与锁文件；宿主插件保留 manifest、命令与技能路径；板端程序保留板型配置与交叉编译目标；Python 应用可用 `src/<app>/` + `configs/` + `scripts/` + `outputs/`（忽略提交）；ROS 多包系统保留 `<name>_interfaces/`、`<name>_driver/`、`<name>_bringup/`（含 `launch/`、`config/`、`maps/`、`rviz/`）与 `dependencies.repos`，源码仓绝不包含本地工作区产物 `build/`、`install/`、`log/`。
- **禁止越界**：禁止表现层/UI/渲染进程与硬件控制/主进程/持久化逻辑交叉渗透；禁止将个人标定、密钥或现场覆盖值提交进默认配置；禁止 `examples/` 或 `scripts/` 复制一套分叉业务实现；禁止静默吞错或写无边界 fallback 掩盖启动/硬件契约失败。
- **最小可执行不变量**：按 Feature Map 从真实入口驱动至少 1 条核心用户动作（Web/CLI 回放、无硬件 `launch` 回放、或插件清单加载），验证输出或状态变化符合预期，且运行产物仅写入忽略目录。

### `assets`：物理与场景资产

- **交付物与入口**：可被多项目通过稳定资产 ID 消费的机器人、物体、静态环境与组合场景，按资产类型直接平铺在根目录，不再套 `assets/assets/` 或空源码包。
- **布局与生态优先**：自有资产库采用 `robots/<id>/`、`objects/<id>/`、`environments/<id>/`、`scenes/<id>/`（按需）、`manifests/`、`tools/`、`docs/`。单项资产目录含 `README.md`（来源、单位、坐标系、版本）、`LICENSE`、真实模型文件（URDF/MJCF/USD/glTF）、`meshes/`、`textures/`。引擎或厂商包要求扁平路径时保留原生布局并提供索引。
- **禁止越界**：禁止以本机绝对路径引用网格或贴图；禁止把仓库代码许可证自动套用到外部第三方模型；禁止把采集轨迹、训练权重混入资产树；禁止将视觉网格默认等同于物理碰撞、惯性或接触参数；禁止把可重建的临时转换缓存当作正式产物提交。
- **最小可执行不变量**：所有模型文件的相对网格/贴图引用均可解析，每项资产存在明确来源与许可记录，且至少一个目标加载器可无报错打开代表性模型并核对单位与关节方向。

### `dataset`：版本化数据发布

- **交付物与入口**：面向下游训练或评估消费的版本化数据集说明、格式 Schema、文件清单与标准划分；大体积实体（视频、HDF5、Parquet、bag）存放于对象存储或发布平台，不进普通 Git。
- **布局与生态优先**：发布平台自带布局与元数据（如 Hugging Face Hub / LeRobotDataset）优先，不复制冗余清单。自有数据发布仓采用 `README.md`、`schemas/`、`manifests/`、`splits/`、`samples/`、`tools/`、`docs/`。格式版本与数据版本独立编号。
- **禁止越界**：禁止仅靠 `final`、日期或手工改名标识版本；禁止在多个下游训练仓各自维护分叉的 Schema 副本；禁止把示例占位路径写成已验证存在的真实资源；禁止训练集与验证/测试集存在样本 ID 泄漏；禁止原始采集数据与派生处理数据混层覆盖。
- **最小可执行不变量**：按发布清单可读取代表性小样本并校验哈希/摘要与 Schema 字段；划分检查确认 `train` 与留出集标识交集为空。

### `content`：知识与出版

- **交付物与入口**：面向读者的知识库、规范文档、学术主页或论文源稿，由首页、索引页或论文主文档作为唯一阅读入口。
- **布局与生态优先**：单篇规范一份 Markdown 即可交付；内容增长后按主题目录或出版工具（VitePress、Jekyll、LaTeX 等）原生结构组织。保留站点既有 URL、相对资源路径与 `CNAME`；若源码分支与发布分支分离，须在 README 显式标注。配图统一归入 `docs/media/` 或出版工具指定静态目录。
- **禁止越界**：禁止留下死链、失效图片引用或孤立无入口的正文页面；禁止在文档里粘贴未经验证且已过期的命令或伪造输出；禁止把交互式软件产品强行按纯内容仓管理。
- **最小可执行不变量**：全仓本地相对链接与媒体资源引用零断裂；需要构建的站点/论文可按文档记录的命令完成本地构建或导出，首页可到达代表性正文。

### `research`：可复核实验研究

- **交付物与入口**：经对照实验得到的可复核结论与定稿报告，从主报告直接定位研究问题、对照条件、输入版本、指标定义与结果。
- **布局与生态优先**：小实验一份主报告即可引用既有代码仓与数据清单；系列实验采用 `configs/`（对照条件）、`scripts/`（复现入口）、`reports/`（定稿报告与选定图表）、`docs/`。完整日志与权重通过不可变运行 ID、版本号或校验值外置引用。
- **禁止越界**：禁止报告中出现无法追溯到 `(code_rev, config, dataset_ver, run_id)` 的孤立数字；禁止手工修改图表数据或只保留最好结果而隐藏失败/最差案例；禁止把大量训练日志、中间权重直接提交进研究仓。
- **最小可执行不变量**：主报告引用的配置、数据版本与代码提交号完整可解析；用保存的代表性小样本重算至少一个汇总指标，结果与报告记录在声明容差及聚合口径内一致。

### `workspace`：多仓集成工作区（组织拓扑）

- **交付物与入口**：可复现的多仓组合与联调入口，由根 README 说明各成员仓职责、接口边界、版本锁定来源和联调顺序。
- **布局与生态优先**：复用 `.gitmodules`、ROS `.repos` 或其他组件锁定清单；根层仅维护跨仓组合配置、接口契约与集成验证脚本。各成员仓保持自身独立 Git 历史、依赖锁文件与发布周期。纯项目书签目录仅维护索引表即可，不必建成工作区。
- **禁止越界**：禁止在工作区根层直接修改成员仓内部实现或破坏成员仓工具链；禁止仅追踪浮动分支名而不记录复现所需的精确提交；禁止为归档到同一研究方向而合并无耦合关系的独立仓库。
- **最小可执行不变量**：从干净检出按根层清单可核对各成员仓实际提交号与相对接口路径，并跑通一次跨组件握手或样本传递检查。

## 3. 场景文件归属表

不同层次的“场景”属于不同交付物，不应为统一命名强行合并：

| 文件是什么 | 归属位置 |
| --- | --- |
| 桌子／房间等可复用静态模型 | `assets` 仓 `environments/<id>/`（软件仓内少量专属为 `assets/environments/`） |
| 多资产实例及摆放关系组成的可复用 USD/MJCF 场景 | `assets` 仓 `scenes/<id>/` |
| 某次任务的数量、摆放范围、相机选择 | `app`/`lib` 仓 `configs/scenes/` |
| reset、随机化、奖励、终止与成功判定逻辑 | `lib`/`app` 源码中的任务模块 |
| 单次运行实际采样出的摆放与物理参数 | 运行输出 `outputs/<run_id>/` 或 episode 元数据 |
| 导航地图／路线图 | ROS bringup 配置包或版本化 `assets` 环境资源 |

## 4. 演进与拆分阈值、按需扩展

多个研究方向可共享同一仓库；拆分只看**独立版本、消费者、许可、存储或运行环境**。

| 演进节点 | 触发拆分的信号 | 目标动作 |
| --- | --- | --- |
| 单脚本 → `lib` / `app` | 被第二个项目复用，或需要配置与回归测试 | 提取正式包结构，建立 Feature Map 与最小检查 |
| 应用内含模型 → 独立 `assets` | 多个仿真/控制项目消费同一套机器人或场景，或模型许可独立 | 抽出 `assets` 仓，原仓按版本或清单引用 |
| 应用内含数据 → 独立 `dataset` | 数据需要独立版本号、公开分发或跨模型复用 | 抽出 `dataset` 仓，原仓只保留读取代码 |
| 实验探索 → `research` 仓 | 需要冻结对照条件与外部可复核报告，且代码仓持续演进 | 抽出 `research` 仓锁定 `(code_rev, dataset_ver)` |

### 可组合但不默认创建的扩展目录

| 扩展 | 何时创建 | 禁止滑坡成 |
| --- | --- | --- |
| `deploy/` | 有实际容器、服务或设备部署描述 | 第二套业务实现或密钥仓库 |
| `environments/` | 一仓确需多个不兼容运行环境定义 | 小项目强制层级；与资产环境模型混淆 |
| `benchmarks/` | 需要独立性能或任务评估程序 | 存放大体积评估输出 |
| `schemas/` | 确有机器可读的外部格式契约 | 与自动生成绑定冲突的手工副本 |
| `third_party/` | 必须随仓维护的第三方源码 | 随意复制全部依赖 |
| `packages/` | 确需多个独立安装/发布的软件包 | 为每个普通子模块建包 |
| `notebooks/` | 确有探索、可视化或解释需求 | 生产流水线的唯一实现 |

同一仓不要同时维护 `docker/` 与 `deploy/docker/` 两套同用途配置。
